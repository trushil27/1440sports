# n8n Workflow — Phase 2.1 Prompt Replacements

**Workflow file:** `1440 Daily Intelligence Brief.json` (12 nodes)
**Last refreshed:** 21 May 2026 (Phase 2.1 rollback to /100)
**Applies to:** the two HTTP-Request nodes that call the Anthropic API.

The other ten nodes (schedule trigger, code parsers, Outlook send, Google Sheets log, Railway PDF builder call, loop guard) carry no prompt logic — they don't need to change for Phase 2.1. They only need to handle the new `score_cells` denominators (`/ 20` instead of `/ 25`) when they pass payload through to the Railway builder. That's parameterised on the model output, so no code edit is required — just retest end-to-end after the prompt swap.

---

## What changes in this document

1. The **Anthropic — Run Signals** node prompt is rewritten to score across **5 dimensions × /20 each (total /100)** instead of 4 dimensions × /25 each.
2. The **Anthropic - Write Brief** node prompt is rewritten so the score-cell grid, BRIEF_DATA template and calibration reference all reflect /20 per cell and /100 total — including the new `operational_fit_section`, `operational_fit_content`, `confidence_level`, and `hot_top_tier` fields the Railway builder now consumes.
3. Calibration anchors are rebuilt against the **Cerebras N°007** reference brief, with scores linearly rescaled (24/25 → 19/20, 21/25 → 17/20, 19/25 → 15/20) and a 5th OPS FIT score added.
4. Operative gate is restated: **Operational Fit only counts toward Top 3 ranking when Brand Fit ≥ 12/20**. Below that gate, OF is recorded but excluded from the ranking sort. This protects against high-OF, low-narrative-fit scores carrying a target into the brief writer.

## Worked example — the Datadog N°011 duplication and its fix

The Datadog brief (N°011, May 2026) carried the team-fit claim "Aston Martin is where the data-infrastructure narrative is being publicly built" in BOTH the page-1 deck AND the page-2 WHY ASTON MARTIN paragraph. The fix is structural — the deck must drop the team claim entirely.

**Before (duplicated):**
- Deck: "An observability category-leader has just crossed its first $1B revenue quarter. Two direct competitors are already on the F1 grid; the slot that matches Datadog architecturally is open at Aston Martin, where the data-infrastructure narrative is already being built."
- WHY ASTON MARTIN: "Aston Martin Aramco is the only team on the grid where the data-infrastructure narrative is being publicly built rather than already owned. CoreWeave is in seat as compute partner; the observability layer over that stack is the natural commercial pairing and is uncontested."

**After (clean):**
- Deck: "An observability category-leader has just crossed its first $1B revenue quarter. The brand-reckoning moment has arrived, two direct competitors are already on the F1 grid, and the architecturally correct slot is open."
- WHY ASTON MARTIN: (unchanged) "Aston Martin Aramco is the only team on the grid where the data-infrastructure narrative is being publicly built rather than already owned. CoreWeave is in seat as compute partner; the observability layer over that stack is the natural commercial pairing and is uncontested."

The deck now names neither Aston Martin nor the data-infrastructure claim — both are reserved for WHY [TEAM]. The reader still sees the team name on the score row immediately below the deck (it's already in the "RECOMMENDED TEAM" mini-cell), so no information is lost — only the narrative argument for the team is held back to the section that exists for it.

## Smoke test after swap

1. Run the workflow manually in n8n. The `Anthropic — Run Signals` node should return ten signals each with `score_breakdown` containing five fields summing close to the top-level `score`.

If the deck names the team narratively (e.g. "where the X narrative is built", "the only team that does Y"), the brief fails this check and must be regenerated.
5. **Anti-hallucination check** — pick three specific claims at random from the rendered brief (a named person, a dollar figure, a competitor sponsorship). Cross-reference each against the signal data passed to the writer (visible in the n8n execution viewer for the prior node). Each must trace back. If any claim is in the brief but not in the signal data and not in the loaded skill context, the brief failed the £100 test — regenerate with the prompt as-is (usually fixes itself) or escalate to manual review.
6. The `1440 Builder — Render PDF` node passes BRIEF_DATA directly to the Railway service. No code change there — but cross-check the rendered PDF shows `OPPORTUNITY  /  100` on the hero, five score cells reading `/ 20`, and the WHAT COULD RUN ON THE CAR section only when OF ≥ 14.
